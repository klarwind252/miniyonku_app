## ③ 要判断（コードは変えていない）
READY（待機）中に S/G のビームが一瞬でも切れる（車を並べる手・車体）と、走行式（TA）として自動でON TRACKに入り **赤（本体/リモコン）は「not READY」で無視**される＝シグナルも音も出ない。
GWシリアルに `[TA] START` → `[SEQ] ignored: not READY` が並べばこれ。対処案：(A) 運用で「灰→赤」／(B) 「走行式で自動開始してから N 秒以内・周回未確定なら赤でシグナルスタートに切替」をファームに追加（挙動変更のため要判断）。

## ハード側の確認（リモコン）
- XIAO ESP32C3 は**外部アンテナ必須**（IPEX）。抜け・LiPo/金属との密着で到達距離が極端に落ちる。
- 常時起動版はUSB給電前提（LiPo 400mAh では約4時間）。

## 追記（同日）サーバーPUSHと実稼働の分離
- PUSH（HTTPS）は 2026-10-31 P2 で既に **netタスク（core0）** に移っており、loop（core1）はTLSで止まらない。
- 残っていた接点＝`flush_spool` が spool_lock 下で行うファイル全読み／送信済み行の書き戻し（フラッシュ消去・書込み）。計測中に重なると loop の `spool_append` がロック待ちで止まる。
- 修正：`tick_flush()` に「計測中（ARMED/GREEN/RACE）は送信を始めない」を追加（要求は保持し FINISH/待機で再開）。
- 根治（次段・要判断）：スプールのRAM化（通過ごとのLittleFS書込みを無くす）。起動時にスプールを全消ししている現行では、フラッシュに置く利点は容量だけ＝B1クリーン構成版（RAMスプール）の本線化で解決する。
